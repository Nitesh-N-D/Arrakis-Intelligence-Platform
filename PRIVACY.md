# Privacy

Arrakis processes account information, focus-session state, distraction logs, profile and roadmap data, settings, and team membership to provide the platform features. Authentication uses access tokens and a refresh-token cookie. The extension stores its configuration and activity buffer in browser extension local storage. When the authenticated Arrakis app is open on the trusted production or local development origin, it transfers the short-lived access token to the extension for authorized synchronization; the extension also retains manual token configuration for local setups. Logging out clears the extension token. Changing accounts clears queued activity to prevent cross-account attribution.

## Browser activity

The extension observes the hostname of visible, focused HTTP and HTTPS tabs and accumulates time in ten-second increments. It synchronizes the hostname, duration, a generated event identifier, and derived broad category to the configured Arrakis API. Pending sync records expire after 24 hours. The current source does not transmit full page URLs or page titles. When a blocked site redirects to the extension's block page, the original destination is held in in-memory extension session storage for up to ten minutes so a timed override can continue to it. The extension page URL contains only a random context identifier, and the destination is removed after use or expiry; session storage is cleared when the extension reloads or the browser restarts.

The authenticated leaderboard displays operative names, ranks, focus streaks, Spice totals, and team names; it does not expose account email addresses. For backwards compatibility, the API accepts URL and page-title fields from older clients but discards them; newly submitted distraction records store hostname and duration without full URLs or page titles. Older extension builds may have sent those fields, and existing records can still contain them until the user exports or deletes the account. The checked-in `arrakis-extension.zip` includes the current source, but publishing it still requires the existing release process. Settings provides a JSON export and account deletion flow. Deletion requires a recently authenticated session, matching account email, and (for local-password accounts) the current password; Google-linked accounts must also enter the explicit confirmation phrase. It transactionally removes the user's profile, focus sessions, distraction logs, roadmap, daily missions, goals, and refresh-token records. The JSON export includes missions and goals. Team membership is removed and owner status transfers to the oldest remaining member; an empty team is deleted. By default, focus and distraction history is kept until the user deletes their account. In Settings → Keep activity history the user can choose 30, 90, 180 or 365 days instead. Older focus sessions and distraction logs are then deleted the next time the user's insights are computed. Removal happens when insights load, not on a background schedule.

## Extension policy sync and tracking pause

When signed in, the extension downloads the account's blocking policy (blocked hostnames, strict mode, override minutes, when blocking applies, whether tracking is paused, and whether a focus session is active). It adopts the policy only when it belongs to the same account as the extension's token. Popup changes are sent back to the account. **Pause activity tracking** in Settings stops the extension buffering activity, and the API discards extension logs while it is on. Manual logs are unaffected.

## Team sharing

Settings stores a team-sharing choice (weekly totals or nothing), and each goal has a "share with team" flag. These choices are stored but no team feature reads them yet. Teammates currently see only the existing leaderboard fields described above, never site names, mission text or goal text.

## Mentat and third parties

With `MENTAT_PROVIDER=heuristic`, Mentat uses server-side deterministic rules and makes no AI-provider request. With `MENTAT_PROVIDER=gemini` or `openai` and a configured key, the server sends aggregated seven-day focus and distraction totals, derived analytics, a small skill-gap summary, streak information, and the user's question to the selected provider. It also sends best-focus hours as hour/share pairs, session-completion and consistency rates, and today's mission counts (total, done, open priorities). It does not send raw browser activity, site names, mission or goal titles, full URLs, page titles, email addresses, or authentication tokens. Mission titles and top distraction sites are used only by the on-server heuristic. AI-generated answers are advisory text: they never write to the database. Google's or OpenAI's terms and privacy policy govern their processing of requests. Provider outages or missing keys use a response labeled as heuristic fallback.

## Retention and security

Focus sessions, distraction logs, refresh-token hashes, profile data, and roadmap/team records are persisted in MongoDB. Refresh-token records expire through the database TTL index; focus and distraction history is retained until account deletion or until the user's chosen retention period expires (see above). Users can export their account data or delete their account in Settings; deletion is transactional and team-aware as described above. The API avoids logging request URLs in production and does not log request bodies. Configure production credentials only in the server environment; never use `VITE_` variables for provider keys.
