# Engineering audit

Audit date: 2026-10-19. Scope was source inspection, baseline build/import/syntax validation, and targeted changes. No production database, credentials, or deployment were accessed.

| Priority | Confirmed finding and code path | Risk / impact | Change | Remaining work |
|---|---|---|---|---|
| Critical | `POST /focus/harvest` accepted client duration and timestamps, created completed sessions, then incremented Spice on every request. | A logged-in user could claim rewards without waiting; retries could duplicate rewards. | Replaced the flow with server-created running sessions, server-clock completion checks, a transaction for completion and Spice, pause/resume/recovery, and a unique active-session index. Legacy harvest now returns 410. | Integration tests against MongoDB replica set are still needed. Standalone MongoDB cannot complete harvest requests. |
| High | Refresh rotation read a valid token, revoked it, then issued another token in separate operations. | Concurrent refresh requests could both succeed. | Rotation now atomically consumes a non-revoked, unexpired token before issuing its successor. | Integration test against MongoDB replica set is still needed. |
| High | Google OAuth linked an existing account by email without requiring the provider email to be verified. | Unverified identity could attach to an existing account. | Only verified Google email addresses proceed to account lookup/linking. | Exercise Google OAuth callback with test identities and confirm provider profile shape. |
| High | Local user records defaulted `googleId` to explicit `null` while the field had a unique sparse index. | MongoDB indexes explicit null values in a sparse index, so creating multiple local users could collide on the unique `googleId` key. | Removed the null default so local accounts omit the optional field; linking Google continues to set a string ID. The replica-set fixture now creates multiple simultaneous local users. | Existing null-valued account records and the current production index still need observation in the owner-controlled deployment. |
| High | Socket middleware accepted connections without a token. | Unauthenticated sockets could connect and receive any future global emissions. | Socket connections now require a valid access token and are only joined to that user's room. | Disconnect at access-token expiration and test room/event authorization in a live Socket.IO integration. |
| High | Mentat had only OpenAI and heuristic selection, no output validation, and sent the full dashboard context to OpenAI. | Requested Gemini path absent; unbounded provider output and excess data disclosure. | Added Gemini SDK adapter using the current `responseSchema` and separate `systemInstruction` configuration, schema/range validation, compact context, timeout, Retry-After-aware single retry for transient errors, explicit fallback, per-user route limits and process-local daily ceilings. Preserved OpenAI and heuristic routing; signals are retained from authoritative server calculations. | Provider calls were mocked; no live credentials or quota check. Process-local budgets do not coordinate across instances. |
| Medium | Focus and distraction aggregation emitted only active days, grouped dates in server local time, and productivity averaged daily means without weighting by sessions. | Empty days disappeared and weekly productivity could be biased. | Series now fill seven UTC days; date boundaries use UTC; productivity weights each daily average by session count. | Existing chart and dashboard calculations need additional product review; UTC may not match a user's chosen timezone. |
| Medium | Production Morgan `dev` logging included request URLs; error handler logged full exceptions. | Query-string identifiers or provider errors could enter logs. | Production access logging omits URL; production error logs include only status and error type, and 5xx responses are generic. | Review Render log retention and current deployment configuration. |
| Medium | Database startup used Mongoose `syncIndexes()` and dropped named legacy indexes. | Startup could remove indexes outside the declared schema and cause unexpected production query regressions. | Startup now creates required refresh-token indexes without reconciling or dropping unrelated indexes. SIGINT/SIGTERM close Socket.IO and MongoDB cleanly; startup/shutdown logs no longer print exception details. | Shutdown path is reviewed and syntax/import checked; live Render termination was not exercised. |
| Medium | Leaderboard queries returned email addresses; team member population also selected them, and client-supplied limits were uncapped. | Private account information was disclosed to authenticated users and queries could be oversized. | Removed email from leaderboard/team population and response; leaderboard limits are clamped to 1–50. Rate-limit IP identity now trusts Express's configured `req.ip` rather than the spoofable first forwarded header. | Add API-level privacy and limiter integration tests. |
| Medium | `ProfileService.updateSettings` spread a Mongoose preferences subdocument directly into an update object. | Mongoose internal fields were included; settings requests returned success while persisted preferences stayed unchanged. | Convert the subdocument to a plain object before merging. Replica-set integration asserts stored strict mode, warning threshold, and blocked sites after save. | Broader settings API validation tests remain useful. |
| Medium | Team creation and membership changes updated team member IDs, user team references, and leaderboard totals in separate writes. | A failed or concurrent membership change could leave users in multiple teams or stale aggregate values. | Create and join flows now re-read the user in a MongoDB transaction, update membership references together, and recalculate affected totals before commit. The replica-set test races two joins and verifies exactly one membership and matching Spice/streak aggregates. | Live team leaderboard behavior has not been exercised against the production deployment. |
| Medium | Login, registration, profile, settings, and manual dashboard forms had labels without control associations; dashboard controls relied only on placeholder text, and the 404 page nested links around buttons. | Screen readers could miss field names and nested interactive elements created invalid navigation semantics. | Associated labels with form controls, added accessible names to unlabeled controls and autocomplete hints, and made 404 actions direct links. | No automated accessibility scanner or keyboard-only browser run is available. |
| Medium | Extension telemetry sent page URLs and titles; blocked matching also searched the whole URL. Failed sync did not preserve the flushed duration, queue retries stopped without new activity or a browser restart, and the tracked ZIP omitted the background worker's imported `domainRules.js`. The extension also relied on manually pasted short-lived access tokens. | Unnecessary browsing details were stored; URL text could cause false-positive blocking; queued data could remain stuck; packaged extension failed module resolution; extension authentication expired without recovery. | Current source strips legacy titles/URLs from local buffers, sends hostname/duration only, matches hostname/subdomains only, retries stable event IDs using persisted alarms with bounded backoff, eight attempts and a one-day TTL, and limits buffered hosts. The authenticated Arrakis app now hands the current short-lived token to the extension on trusted origins; queued events wait for reauthentication and account changes clear the queue. The ZIP includes the imported module and is checked in CI against source. | Browser lifecycle, token handoff, blocking, and duplicate-delivery behavior still need Chrome/Edge testing. |
| Medium | Blocked destinations were copied into the visible extension block-page query string, including any original URL query parameters. | Sensitive parameters could remain in browser-visible extension URLs and browser diagnostics/history. | Block destinations now stay in `chrome.storage.session` under a random context ID for at most ten minutes; the extension URL contains only that ID, and an alarm removes the record at expiry or it is cleared after override. | Requires Chrome 102+ session storage; browser install and override lifecycle still need Chrome/Edge testing. |
| Medium | Extension installation initialized defaults asynchronously while the popup wrote settings directly to local storage; a save immediately after install could be overwritten by the late defaults write. Concurrent block checks could also redirect the same tab more than once. | First-run settings could be lost and duplicate temporary destination contexts could be created. | Defaults initialization is now shared and awaited by background reads/writes; popup settings use validated background messages. Blocking checks verify the current tab URL and coalesce redirects per tab. | Targeted Chromium smoke test passed; broader Chrome/Edge lifecycle verification remains. |

## Baseline and validation gaps

The repository initially had no tests or server test script. The unit suite covers auth-service and auth-controller behavior, verified Google OAuth linking, auth middleware identity/role checks, environment bounds, focus reward rules, service-level concurrency, and idempotent completion retries, analytics calculations, Gemini response validation and timeout behavior, profile input/settings behavior, roadmap phase progression, extension host matching, override expiration, pending-sync alarm scheduling, Storm event idempotency at the service boundary, rate-limit boundaries, live Socket.IO auth/room/expiry behavior, and refresh-token concurrent consumption at the repository boundary. Registration also bounds skill count and name length. Separate replica-set integration coverage exercises focus reward transactions, persisted profile/settings and roadmap changes, and refresh-token consumption. The frontend build updated tracked `client/dist/index.html`; that generated change was restored after verification. The first new provider test exposed an abort/timeout classification issue, which was fixed before rerunning the suite.

The client has migrated to Tailwind CSS 4.3.3 with its Vite plugin and an explicit legacy config load for the existing design tokens. The generated stylesheet builds with the repository's custom utilities. The README documents Tailwind 4's browser minimums: Safari 16.4+, Chrome 111+, and Firefox 128+. Full and production dependency audits are clean for both applications.

Latest verification: `npm test` passes 53 tests, including mocked Gemini quota/auth/network fallbacks, local Socket.IO room and token-expiry behavior, extension account binding, and retry scheduling; `npm run test:integration` passes all four replica-set integration tests against a disposable local MongoDB 8.2.6 binary installed outside the repository; `npm run check:import` passes; `npm audit` reports zero vulnerabilities for server and client; the client production build succeeds; extension JavaScript syntax, manifest JSON, and ZIP/source parity checks pass. A Playwright Chromium smoke test loaded the MV3 extension and verified popup settings validation/persistence, blocked-site redirect, no destination URL in the block-page URL, strict-mode override suppression, timed override to the original destination, one context under concurrent blocking checks, expiry-alarm scheduling, and context/alarm cleanup after override. A startup probe against a closed loopback port exited 1 and logged only the Mongo error type. Read-only production backend `/health` and frontend root requests returned HTTP 200; this does not verify authenticated behavior or that local changes are deployed. The integration suite covers focus reward transactions, persisted profile/settings and roadmap changes, atomic refresh-token consumption, local-user creation, and concurrent team membership/aggregate consistency. The checked-in CI workflow provisions a disposable MongoDB replica set, but no workflow run exists yet because these changes have not been pushed. Auth controller cookie/serialization/OAuth routing, verified-email OAuth strategy, middleware identity/role, rate-limit behavior, and live socket room/expiry behavior have tests. Chrome/Edge full lifecycle and account-token handoff remain unverified. There is no shared rate-limit store, account deletion/export flow, or documented retention scheduler in the inspected source.
